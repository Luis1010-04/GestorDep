## 4. Investigación de `backend/C:…/x.cov` (condición 5)

**Qué pasó.** Durante la medición del plan corrí un comando así desde Git Bash:

```text
docker compose exec -T app php … vendor/bin/pest … --coverage-php=/tmp/x.cov
```

El argumento llevaba una ruta POSIX. MSYS (Git Bash) la convierte en ruta de Windows antes de pasarla a `docker.exe`. Dentro del contenedor, PHP recibió una ruta relativa que empieza por `C:`, y como el directorio de trabajo es `/var/www/html`, el montaje de `backend/`, la escribió en `backend/C:/Users/luis_/AppData/Local/Temp/x.cov`. Windows no admite `:` en nombres de archivo, así que el montaje lo mostró como `C` seguido del carácter privado U+F03A.

**Reproducción inofensiva**, solo con `echo`:

```text
-- sin MSYS_NO_PATHCONV:
--coverage-php=C:/Users/luis_/AppData/Local/Temp/x.cov
/var/www/html
-- con MSYS_NO_PATHCONV=1:
--coverage-php=/tmp/x.cov
```

El mismo efecto se vio con la ruta del archivo de prueba temporal (`Test file "C:/Users/luis_/AppData/Local/Temp/medir/MedirTest.php" not found`).

**Qué no lo causó:**
- `bin/verificar-cobertura.php` no interviene: solo lee `build/coverage/clover.xml`.
- `make verificar` tampoco: sus rutas (`build/coverage`, `build/coverage/clover.xml`) están dentro de `composer.json` y se resuelven en el contenedor, sin pasar por la conversión de MSYS. Después de las corridas de esta tarea, `git status` no muestra nada parecido.

**Acciones:** la carpeta se revisó (solo contenía `x.cov`) y se borró antes de cerrar el plan. No se modificó `bin/verificar-cobertura.php`. Las mediciones siguientes usaron `MSYS_NO_PATHCONV=1`.

## 9. Notas

- **Docker desde Git Bash en Windows:** se antepone `MSYS_NO_PATHCONV=1` a cualquier comando `docker compose …` que lleve una ruta POSIX como argumento (por ejemplo, `MSYS_NO_PATHCONV=1 docker compose exec -T app php vendor/bin/pest /tmp/…`). Sin esa variable, MSYS convierte la ruta en una de Windows y el contenedor escribe archivos con nombres como `C:/…` dentro del montaje de `backend/` (sección 4). `make` no lo necesita: sus destinos no pasan rutas POSIX como argumento.
- **Comprobación tras la entrega (pedida por el responsable):** `a83777a` y `7b4303e` están en `hito/f1-h4`. `git status --ignored` no muestra ninguna ruta `C:…` ni `x.cov`, y `git ls-files` tampoco la contiene: el archivo nunca se versionó.
